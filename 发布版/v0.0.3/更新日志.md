## 一、这一版改了什么

一句话：**你一次提的八条，全做了**；外加剪贴板那块又按真机反馈收了两轮。

### 1. 候选栏选**前面的**词，后面的拼音不再凭空消失

以前点候选栏里的「苍天」，**整轮输入就结束了**——后面那半截「zhijian」跟着没了。

现在上屏「苍天」，**「zhijian」留在预编辑区里**，候选栏接着给「之间」，
按空格就上屏，不用重新打字。

| | 改前 | 改后 |
|---|---|---|
| 打 `cangtianzhijian`，点「苍天」 | 上屏「苍天」，**「之间」没了** | 上屏「苍天」，候选栏接着是「之间」 |

点**后面**的词（「之间」）时，前面没选的那部分不丢——一起上屏成「苍天之间」。

### 2. 数字键盘打第一个数字，不再跳回文字键盘

很多拨号盘收到第一个数字后会调 `restartInput()`（要按号码格式重新整理一遍）。
以前这时键盘形态被无条件复位成中文——**用户打第一个数字就被弹回文字键盘**，
得重新点一次「123」才能接着输入。

现在：**只在不是宿主重启输入的时候复位形态**。

### 3. 连着打的两块，会学成组合

先打「天道」，再打「符文」——以后打 `tiandaofuwen`，候选栏第一条就是**「天道符文」**。

三条规矩：两块得是**连着的**（中间插了空格标点就不学）；**词库里已有的不学**
（「我想」词库里有，学它只会改词频）；**单字不学**（「的」「我」跟谁连着都是巧合）。

### 4. 选字面板的拼音列表，看得全了

| | 改前 | 改后 |
|---|---|---|
| 面板顶栏的拼音 | 单行 + 省略号，**长了就截断** | 允许折行，高度跟着内容长 |
| 左边音节列 | 按权重瓜分高度，音节一多**每格只剩十几 dp，文字被压扁** | 按内容高度排 + **可以竖向滚** |

### 5. 上下文选词**立刻**生效（不用等模型）

打「结」，再打「guo」：光看拼音只能给「过、国、果……」，排序全靠词频，「过」最常用所以排第一。
但用户明明刚打了「结」，他要的是「**结果**」。

现在拿**词库自己**解决：上一块「结」（jie）+ 这一轮「guo」，在词库里查 `jieguo` → 命中「结果」
→ 后半截「果」提到最前。**一次二分查找（2 μs），不等任何模型**。

> 为什么以前那么慢：端侧重排模型**排不了单字候选**（它的图不接受零行输入），
> 云端消歧要 500 ms 防抖 + 一次大模型往返（1.4 s 起）。
> 用户看到的现象就是「候选第一个显示『过』，得停着不动很长时间才会变成『果』」。

### 6. 剪贴板进候选栏，空格直接上屏

复制一段东西，切回来它就摆在候选栏**最前面**（📋 标记，跟别的候选一眼分得开）：
点一下上屏，或者**按空格上屏**。

它是**一次性**的：

- 上屏（点它、空格上屏、或上屏别的内容）→ 收起
- 退格 → 收起
- 上滑删除、云端纠错改写文字 → 收起
- **换个输入框、切到别的 App 再切回来 → 不会复活**
- 要再出现，等**重新复制**一次（复制同样的内容也算）

不然它一直占着候选栏最前面，空格键一直会把它上屏（想打空格的时候老是被它拦一下）。

密码输入框里不给；设置页里有个「候选栏显示剪贴板」开关，关掉之后**完全不读剪贴板**。

### 7. 长句里的错别字，纠得出来了

老的纠错只纠**整串**——候选词必须和音节数一样长。
一旦打的是一整句（不是词库里的一个词），老规则**根本不触发**。
这正是「大篇幅打文档错别字非常多」的原因：**打得越长，整串越不可能是词库里的一个词。**

现在按**分词结果**找错的那一段：

```
今天 | 西安 | 日服 | 我顶        ← 用户实际打出来的（全是词库里的怪词）
今天 | 仙人抚我顶                ← 纠正后
```

窗口取「连续几个词」（总音节数 ≤ 5），拿这一段的拼音去试近音/错键变体。
两条防乱纠的规矩：窗口的拼音**本身就是个词**就不纠；纠正后的词要在打分上**明显更好**才认。

这个计算不便宜（要试几十种变体），所以**放后台线程**：停手 250 ms 才启动，
打字一点不顿，结果回来了再把纠正后的整句摆到候选栏最前面。

### 8. 下一词：本地那份 1 ms 就到，云端改成「下半句优先」

**本地下一词**（新）：刚上屏「结」，候选栏立刻出现「果」「婚」这些接下来最可能接的字——
全部来自词库，1 ms 出结果。云端那份到了补在后面（它更聪明，但要走一次大模型）。

**云端提示词重写**：以前只让模型给「1~3 个汉字的词」，模型给的是「结」「发」「受」「长生」这种碎片。
现在明确要求「**古诗名句、成语、俗语的后半句，必须给出下半句**」，并把词组/短句的长度上限放宽到 6 字。

实测（手机直连的模型，同一条上文连跑三次都稳）：

| 上文 | 改前 | 改后 |
|---|---|---|
| 仙人抚我顶 | 结 / 发 / 受 / 长生（碎片） | **结发受长生** ✅ |
| 今天天气 | 的 / 了 / 是 | **真不错 / 很好 / 非常好** ✅ |

## 二、这一版没做什么（也是实测否决的）

### 换更大的端侧重排模型：只 +0.6pp，延迟 4 倍

上游 chinese-ime-lm 同一个 release 里还有一档更大的（`rerank-8x448`，25M 参数 / 30.8 MB，
格式完全兼容，三个文件改个名就能替换）。拿**我们自己的 3997 条候选池**、
**我们线上这份 Kotlin 实现**实测：

| 模型 | 引擎首选 | 重排后 | 提升 | 延迟 中位 / p95 / 最大 |
|---|---|---|---|---|
| 6x256（8M，线上这份） | 76.3% | **81.0%** | +4.7pp | 7.2 / 15.3 / 41 ms |
| 8x448（25M） | 76.3% | **81.6%** | +5.3pp | **28.9 / 65.3 / 176 ms** |

**+0.6pp 换 4 倍延迟 + 31 MB 体积**，不划算。按键路径一帧（16 ms）放不下 29 ms；
只有走「停手后」才划算——但 0.6pp 撑不起那 31 MB。

> 上游自己的结论也是一样的：**重排这条路基本到顶了**。
> 它在 56 条整句评测里，正确答案只有 52 条在候选池里，
> 25.5 MB 那个模型把这 52 条全拿下——**再往上要改的是候选生成，不是模型**。

所以这一版把力气花在**候选生成**上：上下文选词（跨界组合）、长句纠错、本地下一词——
都不依赖模型，立刻生效。

### 其他被否的重排模型

| 候选 | 否掉的理由 |
|---|---|
| 知字 30M | **CC BY-SA 4.0**（传染性许可）；int8 版未做精度验证；只看得到光标前 32 字；准确率是作者自报 |
| 0C（`0c-sequence-d512` / `0c-ime`） | **注音 / 繁体**，用不上 |
| Qwen 0.6B / 1.7B 等 | 278 MB~1.7 GB，决策慢一个数量级；上游实测没有一个超过它自己 25.5 MB 那个 |
| HuoziIME | 485 MB **生成式** IME（Qwen3-0.6B），架构不同，做不了候选重排 |

## 三、怎么装

1. 把 `双拼输入法-v0.0.3.apk` 传到手机
2. 点它安装（debug 包，需要允许「安装未知来源应用」；可以直接覆盖安装 v0.0.2）
3. **系统设置 → 语言和输入法 → 虚拟键盘 → 启用并切换到「双拼输入法」**
   （调不出键盘时，长按地球键也能进设置页）
4. 桌面上有图标，点图标进设置页（云端、语音、键盘形态、剪贴板开关都在那儿）

> 荣耀 / 华为等 ROM 偶尔会把输入法抢回厂商输入法，重新切换一次即可；
> 也可以在系统设置里把它设为默认。

## 五、已知限制

v0.0.2 的那些都还在，见 [v0.0.2 更新日志](../v0.0.2/更新日志.md) 的「五、已知限制」。
这一版新增或变化的：

- **剪贴板候选只给一段**：不是剪贴板历史，只给**最近复制的那一条**。
  退格只能收起候选栏里那一块，**不会清空系统剪贴板**（那份内容你可能还要粘到别处）。
- **长句纠错是「猜」的**：它按分词结果找错的那一段，窗口 ≤5 音节，
  认不出来的错字照样认不出来；纠正后的整句是**摆出来的候选**，按空格才上屏，
  不会偷偷改你打好的字。
- **本地下一词给的是短尾巴**（「结」→「果」「婚」），
  完整短句要等云端那份（1.4 s 起）。
- **重排模型没换**（见上面「这一版没做什么」）。
